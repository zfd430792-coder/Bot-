# 💞 Бот знакомств для Telegram

Полноценный бот знакомств на **aiogram 3**, **SQLite** и **Redis**: собственная
капча, пошаговая анкета с фото/видео, поиск как в Дайвинчике (город → область
→ соседние области, возраст подбирается сам), лайки с сообщением, лимит
лайков, автоматическая защита от накрутки, напоминания уснувшим, верификация
анкет, поддержка, реклама между анкетами и админ-панель с модераторами,
статистикой и рассылкой.

Интернет нужен только Telegram: справочник городов (385 городов, 172 региона)
лежит внутри проекта, геокодер — опция.

* **SQLite** хранит данные: анкеты, лайки, жалобы, статистику.
* **Redis** хранит состояние диалогов (FSM): незаконченная анкета переживает
  перезапуск, и бота можно запускать в нескольких воркерах.

## Быстрый старт

Нужен сервер на Ubuntu 22.04+ или Debian 12+ и токен бота от
[@BotFather](https://t.me/BotFather). Остальное установщик сделает сам —
на сервере достаточно одной команды:

```bash
curl -fsSL https://raw.githubusercontent.com/zfd430792-coder/Bot-/HEAD/install.sh | bash
```

По шагам:

1. **Системные пакеты** — ставит git, Python с `venv` и Redis, если их нет,
   и включает Redis в автозагрузку. Если `apt` занят автообновлениями Ubuntu
   (частая история на только что созданном сервере), ждёт, а не падает.
2. **Код** — скачивает проект в `~/Bot-`.
3. **Python-окружение** — создаёт `.venv` и ставит библиотеки.
4. **Настройка** — мастер спрашивает токен и ваш ID (как это выглядит — ниже).
5. **Запуск** — регистрирует бота службой systemd `dating-bot`: он работает
   после закрытия SSH, сам поднимается после перезагрузки и перезапускается
   при сбое. Установщик дожидается, пока бот подключится к Telegram, а если
   запуск не удался, показывает причину из журнала и подсказывает, что делать.

Мастер по шагам спросит токен и ваш ID, проверит их на месте и соберёт
готовый `.env`:

```
┌ Шаг 1 из 4 ────────────────────────────────────────────────────┐
│ Токен бота                                                     │
└────────────────────────────────────────────────────────────────┘

  •  Откройте @BotFather → /newbot → скопируйте выданный токен.
     Выглядит так: 8123456789:AAHdqTcvCH1vGWJxfSeofSAs0K5PALDsaw

  Токен › ······
  ✔  Бот найден: @my_dating_bot (Знакомства)
```

Что мастер делает за вас:

* **проверяет токен** через Telegram и показывает, какой бот нашёлся —
  опечатку видно сразу, а не при первом запуске;
* **определяет ваш ID сам**: предложит написать боту любое сообщение и
  возьмёт ID оттуда. Не нужно искать @userinfobot;
* **проверяет Redis** — установщик уже поставил его, а если бот смотрит на
  другой адрес и там никто не отвечает, мастер предложит варианты;
* **бережёт комментарии** — генерируется полный `.env` со всеми пояснениями,
  а файл закрывается правами `600`, потому что в нём лежит токен.

### Обновление

Та же команда. Установщик подтянет свежий код с GitHub, доставит библиотеки,
если поменялся `requirements.txt`, и перезапустит бота. Настройки (`.env`) и
база (`data/bot.db`) не трогаются, мастер второй раз ничего не спрашивает.
Если обновлять нечего, бот не перезапускается.

Правки в коде, сделанные прямо на сервере, не теряются: установщик
откладывает их в `git stash` и пишет, как вернуть.

### Управление

| Что сделать | Команда |
|---|---|
| Журнал бота | `journalctl -u dating-bot -f` |
| Перезапустить | `systemctl restart dating-bot` |
| Остановить / запустить | `systemctl stop dating-bot` · `systemctl start dating-bot` |
| Сменить токен или админов | `curl -fsSL …/install.sh \| bash -s -- --reconfigure` |
| Лог установки | `/var/log/dating-bot-install.log` |

Мастер подставляет текущие значения, так что при перенастройке можно
поменять что-то одно, а остальное оставить.

Необязательные переменные: `BOT_DIR` (папка проекта, по умолчанию `~/Bot-`),
`BOT_SERVICE` (имя службы), `BOT_BRANCH` (ветка). Например, поставить в `/opt`:

```bash
curl -fsSL https://raw.githubusercontent.com/zfd430792-coder/Bot-/HEAD/install.sh | BOT_DIR=/opt/dating-bot bash
```

## Как это выглядит для пользователя

Управление — **inline-кнопками** прямо под сообщениями: экран правится на
месте, под полем ввода пусто. Нижняя кнопка появляется ровно один раз — на
шаге города, «📍 Отправить геопозицию»: геопозицию Telegram отдаёт только
через неё. После этого шага она сама исчезает.

1. **Капча.** Картинка с 15 клетками, под ней коротко: «Выберите все синие
   квадраты» и правило в цитате. Под картинкой — кнопки с номерами клеток
   1–15, «✔️ Готово» и «🔄 Другая картинка»; выбранная клетка отмечается ✅
   прямо на кнопке.
2. **Приветствие** с кнопкой «▶️ Далее».
3. **Предупреждение о мошенниках** — целиком в цитате, на месте приветствия:
   скам, фишинг, просьбы о деньгах. Кнопка «Принимаю» появляется только через
   5 секунд, чтобы её нельзя было пролистать не читая.
4. **Анкета по шагам:** пол → кого искать → возраст → имя (имя из Telegram —
   одной кнопкой) → фото или видео (до 15 секунд, можно кружком) → о себе
   («⏭ Пропустить») → город или область (либо «📍 Отправить геопозицию») →
   предпросмотр.
5. **Главное меню:** «🏠 Главное меню · Выберите, что нужно» и три кнопки:
   «🔍 Смотреть анкеты», «👤 Моя анкета» и «💬 Поддержка». Настроек нет —
   бот ищет сам.
6. **Лента анкет:** под карточкой «❤️ 49 · 💌 Сообщение · 👎 · 🚨 Жалоба ·
   🏠 Меню» (число — сколько лайков осталось на сегодня; когда лимит кончился,
   об этом скажет всплывающее окно). Первыми — те, кто уже поставил вам ❤️;
   дальше свой город, потом область, а потом бот предложит соседние области
   (см. «География»). При взаимной симпатии бот присылает обоим контакт
   собеседника.
7. **Моя анкета:** поменять можно фото и описание; имя, возраст, город и кого
   искать — через «🔄 Заполнить анкету заново» (те же шаги, лайки и пары
   остаются). Там же — скрыть анкету, пройти верификацию, удалить.

Отдельных разделов «кто меня лайкнул» и «мои пары» нет: кто лайкнул, тот
первым в ленте, а контакт пары бот присылает сразу при совпадении.

### Один экран

Бот не заваливает чат сообщениями: меню, анкета, лента и шаги
регистрации — это **один экран**. Кнопки живут в самом сообщении, поэтому
следующий экран чаще всего встаёт правкой на месте; заменять сообщение
приходится, только когда меняется его вид (карточка с фото, реклама). Ответы
пользователя (возраст, имя, город, команды вроде `/start`) удаляются, а сверху
шага анкеты короткой строкой видно уже заполненное. В переписке остаются
только уведомления: совпадения, лайки, сообщения от администрации. Кнопка
уведомления («❤️ Посмотреть») открывает нужный раздел новым экраном, а само
уведомление остаётся на месте.

Повторный `/start` не плодит копии: прежний экран убирается. Список сообщений
экрана хранится отдельно от диалога (своя «destiny» в Redis), поэтому его не
стирает сброс диалога. `/start` и «🏠 Меню» работают из любого места.
Кнопку можно нажать и на старом сообщении выше по чату — тогда экраном
становится оно, а прежний экран убирается. Кнопки прежних версий тоже не
ломают бота: они ведут в меню или в ленту, а оставшаяся нижняя клавиатура
снимается при первом же нажатии.

### Поддержка

Кнопка «💬 Поддержка» показывает контакт, куда писать с вопросами. Контакт
задаётся в админ-панели: «⚙️ Настройки бота» → «💬 Контакт поддержки» —
можно прислать `@username` или ссылку `t.me/…`. Пока он не указан, кнопку
видит только владелец (с подсказкой, где её включить). Этот же контакт бот
называет в сообщении о блокировке.

## Лайк с сообщением

Кроме обычного ❤️ есть кнопка **💌 Сообщение**. Человек пишет пару строк —
лайк ставится автоматически, а адресату сразу приходит уведомление:

> 💌 **Вам написали вместе с лайком!**
> Анкета и сообщение ждут вас первыми в ленте.
>
> `[ ❤️ Посмотреть ]`

В ленте первой идёт **анкета отправителя вместе с текстом** и строкой
«💘 Вы понравились этому человеку!», кнопки обычные: ❤️ — взаимно, и оба
сразу получили контакты; 👎 — пропустить. Анкета никуда не денется, пока на
неё не ответили: лента показывает её первой, где бы отправитель ни жил и
сколько бы ему ни было лет.

Ограничения те же, что и у обычного лайка: суточный лимит, проверка
антинакруткой, запрет ссылок и приглашений в другие чаты, максимум
300 символов.

## Собственная капча

Готовые капчи (искажённый текст, «нажми на кнопку», примеры на сложение)
обходятся скриптом за пару минут: текст читает OCR, а ответ обычно лежит
прямо в `callback_data` кнопки. Здесь сделано иначе.

| Приём | Что даёт |
|-------|----------|
| Ответ есть только на картинке | ни в сообщении, ни в кнопках подсказки нет |
| Номера клеток нарисованы **вектором** (семисегментные цифры) | не зависит от шрифтов в системе, не похоже ни на один готовый датасет |
| Номера **перемешаны** | кнопка «7» — не седьмая клетка, а та, где нарисована семёрка |
| `callback_data` — случайные токены | по данным кнопки не узнать ни номер клетки, ни ответ: соответствие хранится только на сервере |
| Нужно выбрать **все** верные клетки и ни одной лишней | перебор даёт ~1/455 (3 верных из 15), «выбрать всё» не срабатывает |
| Ловушки: та же фигура другого цвета, тот же цвет другой фигурой | ломает наивную классификацию по цвету или форме |
| Похожие цвета и формы не встречаются вместе | зелёный рядом с бирюзовым или круг рядом с шестиугольником проверяют зрение, а не человечность — таких пар в одном задании не бывает |
| Выбранная клетка отмечается ✅ на кнопке | видно, что именно отмечено, и ошибку можно исправить до отправки: повторное нажатие снимает выбор |
| Сеточная деформация, шум, повороты и дрожание контуров | каждая картинка уникальна, шаблонное сравнение не работает |
| Замер времени | мгновенный ответ (< 2 сек) считается ботовским, долгий — протухает |
| 3 попытки, затем блокировка | подбор становится бессмысленным по времени. Первая блокировка короткая (5 минут): ошибиться трижды может и живой человек. Каждая следующая вдвое длиннее — 5, 10, 20, 40 минут. Успешная проверка обнуляет счётчик |

Каждая неудача выдаёт **полностью новое задание** — исключить неверные
варианты нельзя.

## География: город, область, расстояние

Лента идёт **от ближних к дальним, как в Дайвинчике**, и настраивать
ничего не нужно:

1. **свой город** — а также те, кто указал область целиком;
2. **своя область** — остальные города региона;
3. **соседние области** — по расстоянию, ближние первыми. К ним лента
   переходит не сама: когда своя область кончилась, бот спрашивает
   «Показать анкеты из соседних областей?». Согласие запоминается — в
   следующий раз лента пойдёт к соседям без вопроса. Сменил город (заполнил
   анкету заново) — бот спросит снова.

**Возраст бот подбирает сам:** от года младше до двух лет старше. Написали
«18» — лента ищет от 17 до 20, «30» — от 29 до 32.

Жёстко отсекаются только пол, возраст, баны и уже просмотренные анкеты.
Переход на следующую ступень виден строкой над карточкой: «🗺 В вашем городе
анкеты закончились — дальше вся Самарская область». У анкеты из другого
города видно расстояние: «🚶 ~70 км от вас». Кто уже поставил вам ❤️,
показывается первым, где бы он ни жил и сколько бы ему ни было лет.

**Город указывают по-разному — поиск это понимает.** Кто написал «Самара»,
и кто написал «Самарская область», попадают друг другу в первую ступень:
человек, указавший область целиком, свой для любого её города, и наоборот.
Область узнаётся в любом виде: «Самарская область», «Самарская»,
«Самарская обл», «Подмосковье».

Кто поделился геопозицией, видит расстояние до каждой анкеты. Когда
подходящих людей не осталось нигде, бот честно говорит «Вы посмотрели все
анкеты» и предлагает вернуть пропущенных.

Как это устроено:

* локальный справочник `app/data/cities.json` — 385 городов России, Беларуси,
  Казахстана, Украины и других стран с координатами и регионами;
* распознаются сокращения и опечатки: `мск`, `спб`, `екб`, `нн`, `Алма-Ата`,
  `казан`, `Масква`;
* **если города нет в справочнике** — бот спрашивает область и работает по ней,
  а название посёлка сохраняет как есть (жители одного посёлка всё равно
  находят друг друга);
* геопозиция превращается в город обратным поиском по справочнику;
* ступень и расстояние считаются одним SQL-запросом: `dist_km` и `norm`
  (сравнение названий с кириллицей — встроенный `lower()` её не понимает)
  зарегистрированы прямо в SQLite.

**Приватность.** Точные координаты не показываются никому. При приёме
геопозиции они сдвигаются на случайные ~350 метров, а собеседник видит только
округлённое расстояние («~15 км от вас»). Восстановить адрес перебором лайков
невозможно.

Справочник пересобирается из `tools/build_cities.py`:

```bash
python3 tools/build_cities.py
```

Нужны города за пределами справочника — включите онлайн-геокодер
(OpenStreetMap Nominatim), результаты кешируются в базе:

```env
GEOCODER_ENABLED=1
GEOCODER_EMAIL=you@example.com
```

## Защита и модерация

* **Обязательный @username.** Без него бот не пускает: после взаимной симпатии
  собеседнику просто некуда написать.
* **Лимит лайков** — 50 в сутки по умолчанию, меняется в админ-панели на лету.
  Лимит тратят только **исходящие** лайки. Ответить тому, кто лайкнул вас
  первым, можно всегда, даже при нулевом остатке: человек в этот момент
  ничего не ищет — он решает, отвечать взаимностью или нет, и запрещать это
  бессмысленно. Злоупотребить нельзя: бесплатно лайкнуть можно только того,
  кто лайкнул раньше. Когда лайк бесплатный, счётчик на кнопке ❤️ не
  показывается.
* **Возрастной порог** — задаётся в `MIN_AGE` (по умолчанию 18). Тексты бота
  подставляют выбранное значение сами.
* **Фильтр ссылок** в имени и описании — ни `t.me/`, ни `http://`, ни
  приглашений в чужие чаты. Имя при этом не отвергается из-за украшений:
  эмодзи вырезаются автоматически, а буквы **любого алфавита** сохраняются —
  `Айгүл`, `Олексій` и `Ана` проходят наравне с `Алексеем`.
* **Антифлуд** — ограничение частоты действий на каждого пользователя.
* **Жалобы** приходят только администратору, вместе с карточкой нарушителя
  и кнопкой «🚨 Разобрать жалобы»; разбираются в админке по одной: «Забанить / Запросить верификацию /
  Отклонить / Дальше». Автор жалобы собеседнику не раскрывается, а сам
  нарушитель ему больше не показывается.
* **Кнопки — это просто текст**, и прислать его можно в обход экранов. Поэтому
  каждое действие проверяет, можно ли его сейчас: «Далее» и «Принимаю» до
  капчи ведут на капчу, «Заполнить заново» и верификация без анкеты — к её
  заполнению.

### Автоматическая защита от накрутки

Суточного лимита мало: накрутчик уложится и в него. Бот следит за двумя
признаками машинного поведения.

**1. Скорость.** Живой человек смотрит фото и читает описание. Если реакции
идут быстрее чем за `AF_FAST_SECONDS` (1,2 сек) и так `AF_FAST_STREAK` раз
подряд (12) — анкеты никто не смотрит, кнопку жмут вслепую.

**2. Только лайки.** Даже уложившись в лимит, нормальный человек кого-то
пропускает. Если на последних `AF_RATIO_WINDOW` реакциях (30) доля лайков
достигает `AF_RATIO_THRESHOLD` (95%, то есть 29 из 30) — это «лайкаю всех
подряд», обычно чтобы собрать взаимности и рассылать спам.

Наказание нарастает, потому что оба признака изредка даёт и живой человек:

| Нарушение | Что происходит |
|-----------|----------------|
| **первое** | просим заново пройти капчу — боту это дороже, чем человеку. Пока не пройдена, бот закрыт |
| **второе** | автобан на `AF_BAN_HOURS` (сутки) |
| **третье** | бессрочный бан |

После каждого срабатывания счётчик обнуляется: чтобы получить следующую
ступень, нужна новая полная серия — один лайк после повторной капчи к бану
не приведёт.

О каждом срабатывании администратор получает уведомление с признаком,
деталями («97% лайков на последних 30 анкетах») и готовой командой
`/unban` — последнее слово всегда за человеком. Счётчики видны в статистике.

Выключается целиком: `ANTIFRAUD_ENABLED=0`.

### Роли: владелец и модератор

**Владелец** — тот, чей ID указан в `ADMIN_IDS`. Полный доступ.

**Модератор** назначается прямо в боте: `👮 Модераторы` → `➕ Назначить`
(или `/addmod 123456789`). У него в меню появляется кнопка «👮 Модератор»
вместо админки, и доступно только дежурство:

| | Владелец | Модератор |
|---|:---:|:---:|
| Жалобы на анкеты | ✅ | ✅ |
| Заявки на верификацию | ✅ | ✅ |
| Бан и снятие бана | ✅ | ✅ |
| Поиск пользователя, сообщение от администрации | ✅ | ✅ |
| Статистика | полная | краткая сводка |
| Рассылка | ✅ | ❌ |
| Реклама | ✅ | ❌ |
| Настройки бота | ✅ | ❌ |
| Назначение модераторов | ✅ | ❌ |

Персонал защищён от самого себя: **модератор не может забанить другого
модератора или владельца** — бот откажет. Каждое действие модератора попадает
в журнал с его ID, так что видно, кто что сделал.

Как обычный пользователь модератор живёт по общим правилам: лимит лайков,
капча, антинакрутка и антифлуд действуют и на него.

### Владелец вне ограничений

На тех, кто указан в `ADMIN_IDS`, **не действует ни одно ограничение бота**:

| Ограничение | Владелец |
|---|:---:|
| Суточный лимит лайков | не действует |
| Капча на входе и после антинакрутки | не показывается |
| Антинакрутка лайков | не срабатывает |
| Антифлуд (пауза между действиями) | не действует |

| Напоминания «вы давно не заходили» | не приходят |

Так владелец не может случайно запереть сам себя и не спотыкается о
собственные защиты, пока тестирует бота.

### Верификация

Два сценария:

* **Пользователь сам просит галочку** — бот работает как обычно, в анкете
  появляется зелёная галочка ✅ после подтверждения.
* **Администратор требует проверку** — бот для этого человека закрывается
  полностью, анкета скрывается из поиска. Пока администратор не подтвердит
  заявку, при любом действии бот показывает требование верификации.

Проверка — **кружок**. Его записывают прямо с камеры, поэтому чужое фото или
старое видео не подсунуть. Человек нажимает «🎥 Записать кружок» и получает
задание: назвать вслух код из четырёх цифр (например, `4 7 2 9`) и сделать
одно действие — помахать рукой, показать три пальца, дотронуться до уха и
т. п. Код и действие бот выбирает случайно, задание живёт 10 минут: не
успел — бот выдаст новое.

Принимается только кружок длиной 3–20 секунд, записанный самим человеком.
Фото, обычное видео и пересланный кружок бот отклоняет и подсказывает, как
записать кружок.

Кружок уходит администратору с кнопкой «✅ Проверить заявку». Заявки
разбираются в админке по одной: анкета (чтобы сверить лицо), кружок и что в
нём должно быть — код и действие. Решения: «Подтвердить / Отклонить /
Забанить / Дальше». Для отказа есть готовые причины («Не видно лица», «Не тот
человек», «Код не назван», «Нет действия»), а свою можно написать
сообщением. Кружок проверки в анкету не попадает.

**Пример.** В «⚙️ Настройки бота» → «🎥 Пример верификации» владелец
загружает кружок-пример — можно переслать его из другого чата. Пример видит
над своим заданием каждый, кто проходит проверку. В нём называют код
`1 2 3 4`: настоящим этот код никому не выдаётся, так что сам пример проверку
не пройдёт.

## Реклама между анкетами

Посты показываются прямо в ленте — там, где на них точно смотрят. Создаются
в админ-панели за минуту: название → сам пост → кнопка со ссылкой → частота.

* Пост присылается **как есть**: фото, видео, гифка, форматирование, эмодзи.
  Бот копирует исходное сообщение, поэтому ничего не теряется.
* Под постом — ваша кнопка со ссылкой (например, «Перейти в канал»), а
  кнопки ленты — под следующей за ним анкетой.
* **Частота** задаётся отдельно для каждого поста: раз в N анкет, минимум 3.
  Чаще нельзя намеренно — реклама на каждом шаге разгоняет людей.
* Постов может быть несколько: они идут по очереди, первым — тот, который
  показывали реже остальных.
* Пост убирается с экрана вместе с анкетой, поэтому лента не засоряется.
* Считаются показы. Если исходное сообщение удалить, бот сам выключит пост,
  а не будет ронять ленту.

> Переходы по ссылке Telegram ботам не сообщает — это ограничение платформы,
> а не бота. Чтобы считать клики, добавьте к ссылке свою метку
> (`?utm_source=bot`) и смотрите статистику на своей стороне.

## Напоминания уснувшим

Если человек не заходил `INACTIVE_HOURS` (24 часа), бот напоминает о себе сам.
Текст подбирается по ситуации:

* есть непросмотренные лайки → «Вы понравились 3 людям!» — зовём ответить;
* появились новые анкеты → «Пока вас не было, появилось 12 новых анкет»;
* иначе — короткое напоминание из нескольких вариантов, чтобы не повторяться.

Чтобы это не превратилось в спам:

* не чаще одного раза в `REMINDER_COOLDOWN_HOURS` (72 часа);
* после `REMINDER_MAX_COUNT` (3) напоминаний подряд без ответа бот замолкает
  совсем — счётчик обнуляется сам, как только человек вернулся;
* **ночью не пишем**: местный час считается по долготе из анкеты, тихие часы
  задаются в `QUIET_HOURS_START` / `QUIET_HOURS_END` (22:00–9:00);
* в каждом напоминании есть кнопка «🔕 Больше не напоминать»;
* если человек заблокировал бота, напоминания ему выключаются автоматически.

Выключается целиком: `REENGAGEMENT_ENABLED=0`.

## Админ-панель

Открывается командой `/admin` или кнопкой «🛠 Админ-панель» в меню (видна
только админам). На экране — только заголовок и разделы inline-кнопками,
«⬅️ В админку» возвращает к списку разделов. Действия над человеком (бан,
верификация, сообщение) относятся к открытой карточке, поэтому кнопкам не
нужно нести номер. Команды ниже работают как прежде — они видны в меню
команд Telegram.

| Раздел | Что умеет |
|--------|-----------|
| 📊 **Статистика** | всего пользователей, конверсия в анкету, приток за день/неделю, активность за сутки/неделю/месяц, соотношение полов, средний возраст, лайки, совпадения и доля взаимности, жалобы, статистика капчи, топ городов |
| 📢 **Рассылка** | 9 аудиторий (все, с анкетой, активные за 7/30 дней, спящие, не дозаполнившие, парни, девушки, по городу), предпросмотр, прогресс-бар, учёт заблокировавших бота |
| 🚨 **Жалобы** | по одной: карточка нарушителя и решение — забанить, запросить верификацию, отклонить или «⏭ Дальше» |
| ✅ **Верификация** | по одной: анкета, кружок и задание (код + действие) — подтвердить, отклонить (готовая причина или своя), забанить или «⏭ Дальше» |
| 🔎 **Поиск пользователя** | по ID или @username, полная карточка со статусами и действиями |
| 🚫 **Бан / разбан** | бессрочно или на срок (`7d спам`, `12h реклама`), с уведомлением пользователя; истёкшие баны снимаются автоматически |
| 📣 **Реклама** | посты между анкетами: создание, включение/выключение, частота, счётчик показов |
| 👮 **Модераторы** | назначить и снять, список с ID; модератору приходит уведомление и свой набор команд |
| ⚙️ **Настройки бота** | лимит лайков, контакт поддержки, кружок-пример для верификации, открыть/закрыть приём новых анкет |
| 🛡 **Антинакрутка** | счётчик срабатываний и автобанов в статистике, уведомление с командой разбана при каждом случае |
| 🔔 **Напоминания** | сколько отправлено, сколько людей не заходили сутки+, сколько отписалось |
| ✉️ **Написать пользователю** | сообщение от имени администрации |

Команды для быстрой работы:

```
/admin                      панель
/stats                      статистика
/find 123456789             карточка пользователя
/ban 123456789 7d спам      бан на 7 дней
/unban 123456789            снять бан
/verify 123456789           потребовать верификацию
/say 123456789 текст        написать пользователю
/broadcast                  рассылка
/ads                        рекламные посты
/mods                       список модераторов
/addmod 123456789           назначить модератора
/delmod 123456789           снять модератора
/mod                        панель модератора
```

**Журнал событий** (новые пользователи, заполненные анкеты, баны, жалобы,
верификации, блокировки по капче) приходит в чат из `LOG_CHAT_ID`, а если он не
задан — первому администратору из `ADMIN_IDS`.

## Тесты

Сквозной прогон (324 проверки) проходит весь путь пользователя без обращения
к Telegram — реальный токен не нужен:

```bash
# по умолчанию тест ждёт Redis на порту 6399 в базе 15
redis-server --port 6399 --daemonize yes
python3 tests/smoke_test.py

# либо укажите свой
TEST_REDIS_URL=redis://localhost:6379/15 python3 tests/smoke_test.py

# без Redis вообще (например, на Windows): диалоги в памяти процесса
TEST_REDIS_URL=memory python3 tests/smoke_test.py
```

Поддельный Telegram считает, сколько сообщений бота сейчас видно в каждом
чате, — так проверяется, что бот убирает за собой.

Проверяются: капча (верный ответ, неверный, слишком быстрый, отметки на
кнопках, токены вместо номеров), предупреждение на месте приветствия и
задержка перед «Принимаю», валидация возраста/имени/описания,
ограничение длины видео, запасной путь через область, геопозиция и сдвиг
координат, лента и совпадения, лимит лайков, жалобы, админ-панель, статистика,
**верификация кружком** (только кружок на 3–20 секунд и не пересланный, код
живёт 10 минут, пример из настроек, готовые причины отказа, старые заявки с
фото), бан и разбан, рассылка, **своя анкета** (новое
фото и описание, заполнение заново без потери пар, скрытие и удаление),
**подбор без настроек** (возраст −1/+2, старые кнопки и диалоги прежних
версий ведут в меню), **поддержка** (контакт из админки, кнопка у всех, контакт
в сообщении о бане), **антинакрутка** (скорость, доля лайков, три ступени
наказания, отсутствие ложных срабатываний), **напоминания** (очередь, тихие
часы, отписка, лимит повторов, обнуление при возврате), **настраиваемый
возрастной порог**, **лайки с сообщением** (фильтр ссылок, уведомление с
анкетой и текстом, ответ взаимностью), **модераторы** (урезанное меню, запрет
банить персонал, снятие прав), **реклама** (создание, частота показа,
включение и выключение, счётчик показов), **бесплатный ответный лайк**
(при нулевом лимите можно ответить, но не начать), **снятие ограничений
с владельца**, **режим одного экрана** (шаги правятся на месте, ответы
удаляются, повторный `/start` не плодит копии, кнопка уведомления оставляет
само уведомление в чате), **inline-кнопки** (нижняя — только геопозиция на
шаге города и сразу снимается; старая нижняя клавиатура снимается даже у
вернувшихся спустя недели; `callback_data` в пределах лимита Telegram),
**лента как в Дайвинчике** (кто лайкнул — первым; «Самара» и «Самарская
область» видят друг друга первыми, затем область, затем вопрос про соседние
области, и согласие запоминается; экран конца ленты с возвратом
пропущенных), **кнопки не обходят проверки** («Далее» и «Принимаю» до капчи,
«Заполнить заново» и верификация без анкеты, шаги анкеты и админка по
подделанному нажатию) и **оформление** (предупреждение
в цитате, короткая капча, зелёная галочка).

Отдельно проверяются миграция базы и мастер настройки — обоим Redis не нужен:

```bash
python3 tests/migration_test.py   # база прежней версии открывается без потерь
python3 tests/setup_test.py       # диалог мастера, .env и вёрстка рамок
```

## Запуск на сервере

Службу `dating-bot` создаёт установщик — руками ничего писать не нужно.
Для справки, вот что он кладёт в `/etc/systemd/system/dating-bot.service`
(файл перезаписывается при обновлении, свои добавки — через
`systemctl edit dating-bot`):

```ini
[Unit]
Description=Telegram dating bot
After=network-online.target redis-server.service
Wants=network-online.target redis-server.service

[Service]
Type=simple
WorkingDirectory=/root/Bot-
ExecStart=/root/Bot-/.venv/bin/python main.py
Environment=PYTHONUNBUFFERED=1
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Если папка проекта принадлежит не root, установщик добавит `User=` с её
владельцем.

```bash
systemctl status dating-bot
journalctl -u dating-bot -f
```

Резервная копия — это один файл (`data/bot.db`): в Redis лежат только
незаконченные диалоги, терять их не жалко. База работает в режиме WAL,
копировать можно на ходу:

```bash
sqlite3 data/bot.db ".backup '/backup/bot-$(date +%F).db'"
```

## Заметки по данным

* Хранится минимум: анкета, округлённые координаты, реакции, жалобы и журнал
  модерации.
* Точные координаты не хранятся и никому не показываются.
* Кружок верификации доступен только администратору и в анкету не попадает.
* Удаление анкеты стирает данные профиля, лайки и совпадения; запись о
  пользователе остаётся только для того, чтобы помнить бан и капчу.
